# Свой TURN‑сервер (coturn) для Nox — пошагово

Цель: поднять собственный STUN+TURN, чтобы звонки проходили между любыми сетями (Wi‑Fi ↔ мобильный интернет, разные города, CGNAT). Лучший вариант для РФ: свой сервер стабильнее гугловского STUN и полностью под вашим контролем.

Готовый скрипт делает всю серверную часть: `scripts/setup-coturn.sh`.

Времени: ~15–20 минут. Технического опыта: минимум (копировать/вставлять команды).

---

## Что понадобится

1. **VPS** с публичным IPv4, Ubuntu 22.04/24.04. Хватит самого маленького: 1 vCPU / 1 GB RAM. Важнее CPU — **трафик**: при relay звонок идёт через сервер (аудио ~50–100 кбит/с, видео ~0.5–2 Мбит/с в каждую сторону). Для десятков одновременных звонков берите тариф с безлимитным/большим трафиком.
   - Провайдеры с хорошей достижимостью из РФ: Timeweb, Selectel, VDSina, Aeza, Рег.ру. Нейтральная локация (Нидерланды/Германия/Финляндия) тоже подойдёт, если она у вас стабильно открывается — проверьте пингом до звонков.
2. **Домен** (или поддомен), где вы можете добавить DNS‑запись. Например `turn.noxchat.ru`. Домен нужен для TLS (`turns:` на 5349) — это то, что пробивает строгие файрволы, пропускающие только HTTPS.

---

## Шаг 1. Арендовать VPS

Создайте самый дешёвый VPS (Ubuntu 22.04/24.04). Запишите его **публичный IP** (например `203.0.113.10`) и **root‑пароль** (или загрузите свой SSH‑ключ).

## Шаг 2. DNS: направить поддомен на сервер

В панели вашего домена добавьте A‑запись:

```
Тип: A    Имя: turn    Значение: 203.0.113.10    TTL: 300
```

Проверьте (через пару минут), что резолвится: на своём компьютере `ping turn.noxchat.ru` должен показать IP сервера. TLS не выпустится, пока DNS не указывает на сервер.

## Шаг 3. Запустить скрипт на сервере

Подключитесь к серверу по SSH (с вашего компьютера):

```bash
ssh root@203.0.113.10
```

Скопируйте на сервер файл `scripts/setup-coturn.sh` (варианты: `scp scripts/setup-coturn.sh root@203.0.113.10:~/`, или просто откройте файл, скопируйте содержимое, на сервере `nano setup-coturn.sh`, вставьте, сохраните).

Придумайте **длинный случайный пароль** для TURN (например `openssl rand -hex 24`). Запустите, подставив свои значения:

```bash
sudo TURN_DOMAIN=turn.noxchat.ru \
     TURN_USER=noxturn \
     TURN_PASSWORD='ВАШ_ДЛИННЫЙ_СЛУЧАЙНЫЙ_ПАРОЛЬ' \
     [email protected] \
     bash setup-coturn.sh
```

Скрипт сам: поставит coturn и certbot, откроет порты (3478/5349/relay‑диапазон), выпустит TLS‑сертификат Let's Encrypt (с авто‑продлением), запишет защищённый `/etc/turnserver.conf`, включит и запустит сервис. В конце он **напечатает три готовые строки** `NEXT_PUBLIC_TURN_*`.

## Шаг 4. Прописать env в Nox и пересобрать

Возьмите три строки из вывода скрипта, например:

```
NEXT_PUBLIC_TURN_URLS=turn:turn.noxchat.ru:3478?transport=udp,turn:turn.noxchat.ru:3478?transport=tcp,turns:turn.noxchat.ru:5349?transport=tcp
NEXT_PUBLIC_TURN_USERNAME=noxturn
NEXT_PUBLIC_TURN_CREDENTIAL=ВАШ_ДЛИННЫЙ_СЛУЧАЙНЫЙ_ПАРОЛЬ
```

Куда вставить:
- **Локально/на своём сервере приложения**: в `.env`, затем `npm run build && NODE_ENV=production npm start`.
- **На Railway**: Project → Variables → добавить три переменные → передеплоить (обязательно **пересборка**, а не просто рестарт).

> Почему пересборка обязательна: префикс `NEXT_PUBLIC_` вшивает значения в клиентский бандл на этапе `next build`. Заданные после сборки — не подхватятся.

## Шаг 5. Проверить

1. **Внешняя проверка TURN** (со своего ноутбука, не с сервера): откройте
   https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/ ,
   в «ICE servers» добавьте `turn:turn.noxchat.ru:3478`, ваш username/пароль, нажмите «Gather candidates». В списке **должны появиться кандидаты типа `relay`**. Есть `relay` → TURN работает.
2. **Реальный звонок** между двумя разными сетями (один Wi‑Fi, другой мобильный интернет). В экране звонка встроенный дебаг‑оверлей покажет `TURN: YES`.
3. **Жёсткая проверка** именно TURN: временно поставьте `NEXT_PUBLIC_FORCE_RELAY=true`, пересоберите. Если звонок при этом соединяется — TURN точно рабочий (принудительно используется relay‑путь). Потом верните `false`.

## Обслуживание

- **Сертификат** продлевается автоматически (certbot ставит systemd‑таймер; скрипт добавил `--deploy-hook "systemctl reload coturn"`, чтобы coturn перечитал новый серт).
- **Логи**: `journalctl -u coturn -f`. Статус: `systemctl status coturn`.
- **Пароль сменить**: отредактируйте `user=` в `/etc/turnserver.conf`, `systemctl restart coturn`, обновите `NEXT_PUBLIC_TURN_CREDENTIAL` и пересоберите приложение.
- **Стоимость**: сам VPS дёшев; следите за трафиком (relay‑звонки его расходуют). Не все звонки идут через TURN — только те, где прямой путь невозможен.

## Траблшутинг

- **`relay`‑кандидатов нет в trickle‑ice** → порты закрыты у провайдера (проверьте firewall в панели VPS, не только `ufw`), или `external-ip` неверный. Посмотрите `journalctl -u coturn`.
- **`turns:` (TLS) не работает, а `turn:` работает** → сертификат не выпустился (DNS не указывал на сервер в момент запуска). Перезапустите certbot: `certbot certonly --standalone -d turn.noxchat.ru --deploy-hook "systemctl reload coturn"`, затем `systemctl restart coturn`.
- **В приложении `TURN: NO`** → env не попали в сборку (не пересобрали, или задали после build).
- **Звонок в одной сети работает, между сетями нет** → это ровно тот случай, ради которого нужен TURN; значит TURN ещё не подхватился — вернитесь к шагам 4–5.

## Безопаснее (опционально, позже)

Скрипт ставит статичного пользователя (`user=login:password`) — просто и совместимо с текущим кодом. Более правильная схема — **временные креды**: coturn `use-auth-secret` + общий секрет, а приложение отдаёт клиенту логин/пароль с TTL через серверный эндпоинт (без `NEXT_PUBLIC_`, не вшивается в бандл). Это отдельная доработка кода (эндпоинт `GET /api/ice-servers`), описана в `docs/calls-webrtc.md`. Для старта статичного пользователя достаточно.
